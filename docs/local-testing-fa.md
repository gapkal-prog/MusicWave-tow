# راهنمای دریافت شاخه و آزمایش عملی MusicWave روی سیستم شخصی

این سند مسیر کامل «دریافت کد → راه‌اندازی وردپرس → آزمایش دستی و خودکار» را برای شاخهٔ ارتقای رابط کاربری توضیح می‌دهد. همهٔ دستورها در ترمینال (macOS/Linux) یا PowerShell/Git Bash (Windows) اجرا می‌شوند.

## ۱. دریافت شاخه

شاخهٔ کار: `arena/01a07110-musicwave-project` (روی `main` ساخته شده و شامل کد جدید + همهٔ فایل‌های پروژه است).

**کلون تازه (پیشنهادی):**

```bash
git clone https://github.com/gapkal-prog/MusicWave-project.git
cd MusicWave-project
git checkout arena/01a07110-musicwave-project
```

**اگر از قبل کلون دارید:**

```bash
cd MusicWave-project
git fetch origin
git checkout arena/01a07110-musicwave-project
git pull --ff-only
```

**بدون Git (فایل ZIP):**

<https://github.com/gapkal-prog/MusicWave-project/archive/refs/heads/arena/01a07110-musicwave-project.zip>

پوشه‌های مهم پس از دریافت:

| پوشه | نقش |
| --- | --- |
| `musicwave/` | قالب بلوکی (Site Editor) |
| `music-wave-core/` | افزونهٔ اصلی (کاتالوگ، پخش‌کننده، REST، بلوک‌ها) |
| `music-wave-vip/` | افزونهٔ عضویت/دانلود محافظت‌شده (اختیاری) |
| `docs/ui-upgrade-plan-fa.md` | تحلیل، برنامه و گزارش اجرای همین ارتقا |

## ۲. راه‌اندازی وردپرس محلی

### مسیر الف — `wp-env` (یک دستور، همان محیط CI)

پیش‌نیاز: Docker Desktop در حال اجرا + Node.js 20 یا بالاتر.

```bash
npm ci
npx @wordpress/env start
npx @wordpress/env run cli wp plugin activate music-wave-core music-wave-vip
npx @wordpress/env run cli wp theme activate musicwave
npx @wordpress/env run cli wp rewrite structure '/%postname%/' --hard
# اختیاری: فروشگاه
npx @wordpress/env run cli wp plugin install woocommerce --activate
```

- سایت: <http://localhost:8888> — پیشخوان: <http://localhost:8888/wp-admin> (کاربر `admin`، گذرواژه `password`)
- `WP_DEBUG` روشن است؛ خطاهای PHP در `npx @wordpress/env logs` دیده می‌شوند.
- توقف: `npx @wordpress/env stop` — پاک‌سازی کامل: `npx @wordpress/env destroy`.

### مسیر ب — LocalWP / XAMPP / MAMP (بدون Docker)

1. یک سایت وردپرس ۶.۶ یا جدیدتر با PHP 8.1+ بسازید.
2. کپی کنید:
   - `musicwave/` → `wp-content/themes/musicwave/`
   - `music-wave-core/` → `wp-content/plugins/music-wave-core/`
   - (اختیاری) `music-wave-vip/` → `wp-content/plugins/music-wave-vip/`
3. پیشخوان → افزونه‌ها: **MusicWave Core** (و VIP) را فعال کنید؛ نمایش → پوسته‌ها: **MusicWave** را فعال کنید.
4. تنظیمات → پیوندهای یکتا → «ذخیرهٔ تغییرات» (بدون تغییر) تا مسیرهای `mw_release` ثبت شوند. از نسخهٔ ۰.۱۲.۰ نشانی هر انتشار بر اساس «نوع انتشار» ساخته می‌شود: آلبوم `‎/album/…`، قطعه و تک‌قطعه `‎/track/…`، EP `‎/ep/…`، میکس `‎/mix/…`، فهرست پخش `‎/playlist/…`، پادکست `‎/podcast/…` و قسمت پادکست `‎/episode/…`؛ انتشار بدون نوع همچنان `‎/music/…` می‌ماند و پیوندهای قدیمی `‎/music/…` با ریدایرکت ۳۰۱ به نشانی جدید می‌روند. اگر پس از به‌روزرسانی هنوز نشانی‌ها `‎/music/` بودند، همین صفحه را یک بار «ذخیره» کنید.
5. **MusicWave → راه‌اندازی و عیب‌یابی** → دکمهٔ «درون‌ریزی کاتالوگ نمایشی» تا چهار انتشار نمونه (قطعه، آلبوم، برنامه و قسمت پادکست) با پیش‌نمایش صوتی ساخته شوند. در مسیر الف همین کار با `npx @wordpress/env run cli wp musicwave migrate` + همان دکمه انجام می‌شود.

## ۳. چک‌لیست آزمایش دستی (مرورگر)

ابزار: DevTools → حالت دستگاه (Ctrl/Cmd+Shift+M). هر مورد را در عرض‌های **360، 600، 768، 1024، 1440** پیکسل بررسی کنید.

### ۳.۱ سربرگ و منوی موبایل

- [ ] در عرض کمتر از **1024px** فقط دکمهٔ همبرگر دیده می‌شود؛ در 1024px و بیشتر منو به‌صورت افقی است (هیچ عرضی نیست که هر دو یا هیچ‌کدام دیده شوند).
- [ ] با کلیک روی همبرگر، overlay تمام‌صفحه باز می‌شود، آیتم‌ها زیر هم و قابل اسکرول‌اند، دکمهٔ بستن در گوشهٔ بالا است.
- [ ] `Esc` overlay را می‌بندد؛ `Tab` داخل overlay می‌چرخد (تلهٔ فوکوس)؛ پس از بستن، فوکوس به همبرگر برمی‌گردد.
- [ ] با نوار مدیریت (کاربر وارد شده) سربرگ چسبان زیر نوار مدیریت می‌ماند و overlay روی همه‌چیز است.
- [ ] دکمهٔ جست‌وجو (آیکن ذره‌بین) با کلیک باز می‌شود، با `Esc` یا خروج فوکوس بسته می‌شود.
- [ ] هر **پنج** سربرگ را از **نمایش → ویرایشگر → الگوها → بخش‌های قالب** باز و ویرایش کنید: `سربرگ`، `سربرگ (وسط‌چین)`، `سربرگ (ساده)`، `سربرگ (استریم)`، `سربرگ (استریم — ریل انتها)`.
- [ ] در **نمایش → سفارشی‌سازی → سربرگ MusicWave** سربرگ فعال را عوض کنید: خروجی سایت، کنوس الگوها و دکمهٔ «ویرایش بخش» باید همان سربرگ فعال را نشان دهند. سپس یک تغییر جزئی (مثلاً متن دکمهٔ VIP) را در ویرایشگر سایت ذخیره کنید و در فرانت‌اند ببینید.
- [ ] هیچ صفحهٔ مدیریتی جداگانه‌ای برای سربرگ وجود ندارد؛ **نمایش** باید فقط «سفارشی‌سازی» و «ویرایشگر» را نشان دهد و آدرس `wp-admin/themes.php?page=musicwave-site-header` باید به صفحهٔ «یافت نشد» برسد.
- [ ] دکمهٔ «ویرایش همین سربرگ در ویرایشگر سایت» در توضیح کنترل «سربرگ سراسری» باید همان سربرگ فعال را باز کند.
- [ ] یک سربرگ تازه در ویرایشگر سایت بسازید و تأیید کنید در فهرست «سربرگ سراسری» بخش سفارشی‌سازی ظاهر می‌شود و با انتخاب آن، سراسر سایت عوض می‌شود.
- [ ] **نوار پایین**: در سفارشی‌سازی «موبایل و تبلت» را انتخاب کنید. در هر پنج سربرگ، بلوک «نوار پایین موبایل» باید داخل بخش قالب دیده و قابل ویرایش باشد (افزودن/حذف آیتم، تغییر برچسب و لینک). با «فقط موبایل» نوار بین ۷۶۸ تا ۱۰۲۴ پیکسل پنهان می‌شود. با «خاموش» نوار از همهٔ سربرگ‌ها حذف می‌شود.
- [ ] با خاموش‌بودن نوار پایین، `mw-global-player` به لبهٔ پایین صفحه می‌چسبد و فاصلهٔ پایین صفحه به‌اندازهٔ ارتفاع نوار کاهش می‌یابد (بدون فضای خالی).
- [ ] با روشن‌بودن نوار پایین، خاموش‌کردن «نمایش برچسب» فقط آیکون‌ها را نگه می‌دارد و ارتفاع لمسی هر آیتم کمتر از ۴۴ پیکسل نمی‌شود.
- [ ] صفحه‌های **هنرمندان** (`/artists/`) و **سبک‌ها** (`/genres/`) از منوی سربرگ باز می‌شوند، عنوان صفحه و ویترین‌ها را نشان می‌دهند و لینک هر هنرمند/سبک به آرشیو همان ترم می‌رود.
- [ ] در `/artists/` زیر ویترین، **صفحه‌بندی** دیده می‌شود: «قبلی/بعدی»، شمارهٔ صفحه‌ها، شمارهٔ صفحهٔ جاری با `aria-current="page"` و خط وضعیت «صفحهٔ ۱ از N · M هنرمند». با کلیک روی شماره‌ها آدرس به `?mw_artists_page=2` تغییر می‌کند، هنرمندان همان صفحه می‌آیند و اسکرول به بالای صفحه برمی‌گردد؛ ورود مستقیم به `?mw_artists_page=99` به آخرین صفحه محدود می‌شود (بدون صفحهٔ خالی).
- [ ] در ویرایشگر، ویترین هنرمندان → پنل «سربرگ» → «صفحه‌بندی هنرمندان» روشن است و «هنرمند در هر صفحه» روی ۲۴؛ با تغییر آن، تعداد کارت‌های هر صفحه و شمارهٔ صفحه‌ها هم عوض می‌شود. با «تصادفی» یا منبع «دستی» گزینهٔ صفحه‌بندی پنهان می‌شود، چون این فهرست‌ها تک‌صفحه‌ای‌اند.

### ۳.۲ حالت روشن / تیره

- [ ] دکمهٔ سوییچ پوسته در سربرگ سه حالت دارد (سیستم → روشن → تیره) و آیکن مناسب را نشان می‌دهد.
- [ ] در حالت روشن، متن اصلی تیره (`#0f1115` در تنوع پیش‌فرض) و متن کم‌رنگ خاکستری تیره است؛ هیچ متن سفیدی روی پس‌زمینهٔ روشن نیست.
- [ ] با **نمایش → ویرایشگر → سبک‌ها** هر چهار تنوع (Default، Aurora، Studio، Sunrise) را فعال کنید و هر دو حالت را ببینید.
- [ ] پس از بارگذاری مجدد صفحه، حالت انتخاب‌شده حفظ می‌شود (بدون پرش رنگ).

### ۳.۳ پخش‌کنندهٔ سراسری `mw-global-player`

- [ ] روی دکمهٔ «پیش‌نمایش» یک انتشار کلیک کنید؛ نوار پخش از پایین ظاهر می‌شود و محتوای صفحه زیر آن پنهان نمی‌ماند (فاصلهٔ پایین صفحه اضافه می‌شود).
- [ ] دسکتاپ: کارت شناور وسط‌چین با جلد، عنوان/هنرمند، قبلی/پخش/بعدی، نوار زمان با «سپری‌شده / کل»، صف، بی‌صدا + میزان صدا، بستن.
- [ ] عرض کمتر از **1024px**: میزان صدا پنهان می‌شود؛ نوار زمان زیر کنترل‌ها می‌رود.
- [ ] عرض کمتر از **768px**: نوار به لبهٔ پایین می‌چسبد و تمام‌عرض است؛ کمتر از **384px** دکمهٔ «قبلی» پنهان می‌شود.
- [ ] کلیدها: `Space`/`K` پخش/توقف، `←`/`→` جابه‌جایی ۵ ثانیه؛ صفحه‌خوان مقدار «0:42 / 3:10» را روی نوار زمان می‌خواند.
- [ ] هنگام بافر شدن، دکمهٔ پخش اسپینر نشان می‌دهد و همچنان قابل کلیک است.

### ۳.۴ ناوبری نرم (پخش مداوم بین صفحه‌ها)

پیش‌فرض این قابلیت روشن است (**MusicWave → تنظیمات و نمای کلی → پخش مداوم**).

- [ ] حین پخش، روی یک پیوند داخلی (مثلاً «انتشارها») کلیک کنید: صدا قطع نمی‌شود، URL و عنوان عوض می‌شوند، محتوا جایگزین می‌شود.
- [ ] **بعد از** این ناوبری، همبرگر موبایل و جست‌وجوی بازشونده همچنان کار می‌کنند (اصلاح اصلی این نسخه).
- [ ] آیتم فعال منو (`current-menu-item`) به صفحهٔ جدید منتقل می‌شود.
- [ ] دکمه‌های Back/Forward مرورگر بدون بارگذاری کامل صفحه را برمی‌گردانند و پخش ادامه دارد.
- [ ] پیوند به سبد خرید/تسویه‌حساب/ورود همیشه بارگذاری بومی است؛ پس از آن نوار پخش با همان آهنگ و موقعیت برمی‌گردد (بازیابی از `sessionStorage`).

### ۳.۵ راست‌به‌چپ

- [ ] با زبان فارسی، همهٔ چیدمان‌ها آینه‌ای‌اند: جلد در سمت راست نوار پخش، آیکن‌های جهت‌دار درست، منوها به راست چسبیده.

### ۳.۶ نشانی انتشارها (نوع‌محور)

- [ ] یک آلبوم نمایشی را باز کنید: نشانی با `‎/album/` شروع می‌شود؛ یک قطعه با `‎/track/`؛ یک قسمت پادکست با `‎/episode/`.
- [ ] نشانی قدیمی همان آلبوم را دستی وارد کنید (`‎/music/<slug>/`): با ریدایرکت ۳۰۱ به `‎/album/<slug>/` می‌رود و صفحه ۴۰۴ نمی‌دهد.
- [ ] آرشیو `‎/music/` و آرشیو نوع (`‎/release-type/album/`) مثل قبل کار می‌کنند.
- [ ] `‎/album/<slug>/feed/` و `‎/album/<slug>/embed/` پاسخ می‌دهند (permastruct کامل است).

### ۳.۷ صفحهٔ تک‌انتشار در موبایل و تبلت

- [ ] عرض ۳۶۰ و ۷۶۸: هیرو از لبهٔ صفحه بیرون نمی‌زند، نوار دکمه‌ها وسط‌چین و قابل لمس است.
- [ ] «فهرست قطعه»: در موبایل هر ردیف دو خط است (عنوان + هنرمند؛ زمان و دکمه‌ها در یک ردیف)، در تبلت ستون هنرمند باریک‌تر و ستون کیفیت پنهان است؛ دکمهٔ پیش‌نمایش با انگشت راحت زده می‌شود.
- [ ] بخش «دیدگاه شنوندگان» زیر قطعات مرتبط نمایش داده می‌شود (وقتی دیدگاه‌ها باز باشند یا دیدگاهی وجود داشته باشد)؛ فرم ارسال دوستونه است و در عرض کم یک‌ستونه می‌شود؛ پاسخ تودرتو و صفحه‌بندی درست است. برای انتشارهای قدیمی، «دیدگاه‌ها» را از ویرایش سریع باز کنید.

### ۳.۸ قفسه‌های افقی و گالری فهرست پخش

- [ ] در قفسهٔ افقی (`mw-release-shelf--scroll`) دکمهٔ «بعدی» به اندازهٔ کارت‌های قابل‌مشاهده جلو می‌رود و در انتها غیرفعال می‌شود؛ «قبلی» برعکس. در فارسی جهت حرکت با جهت خواندن یکی است و فلش‌ها آینه‌ای‌اند.
- [ ] اگر همهٔ کارت‌ها در عرض جا شوند، هر دو فلش پنهان/غیرفعال هستند.
- [ ] کارت‌های «فهرست‌های پخش انجمن»: جلدها به‌صورت پشتهٔ بادبزنی روی هم چیده شده‌اند و با hover کمی باز می‌شوند؛ فهرست خالی یک جلد با نُت نشان می‌دهد؛ حالت‌های دایره/افقی/عمودی و نمای فهرستی درست‌اند.

### ۳.۹ جست‌وجوی فارسی

- [ ] یک انتشار با عنوان فارسی بسازید (مثلاً «آهنگ‌های پاییزی»)؛ سپس همان عبارت را در جعبهٔ جست‌وجوی سربرگ با شکل‌های مختلف تایپ کنید: با «ي/ك» عربی، با فاصلهٔ معمولی به‌جای نیم‌فاصله، با اعداد فارسی/انگلیسی. در هر حالت همان انتشار در `/?s=…` پیدا می‌شود و پیام «نتیجه‌ای پیدا نشد» نمایش داده نمی‌شود.
- [ ] کلمه‌ای را جست‌وجو کنید که فقط نام هنرمند، ژانر یا حال‌وهوا است (نه در عنوان و متن)؛ انتشارهای آن ترم در نتایج می‌آیند.
- [ ] عبارت دو‌کلمه‌ای: هر دو کلمه باید در (عنوان/متن/ترم/متادیتا) وجود داشته باشد؛ `-کلمه` آن را حذف می‌کند.
- [ ] عبارت لاتین مثل `lofi` مانند قبل رفتار می‌کند (بدون تغییر).
- [ ] پیشنهادهای خودکار سربرگ (`/wp-json/music-wave/v1/catalog/suggest?term=…`) با املای عربی/فارسی هم عنوان‌ها و هم ترم‌ها را برمی‌گردانند.

### ۳.۱۰ درخواست آهنگ سفارشی و همکاری

- [ ] یک برگهٔ جدید بسازید و از «قالب» سمت راست، «درخواست آهنگ و همکاری» را انتخاب کنید (یا بلوک «فرم درخواست همکاری» را در هر برگه‌ای بگذارید). در فرانت‌اند فرم با پنل کناری، چیپ‌های نوع درخواست و سؤال‌های متداول دیده می‌شود؛ در ۳۶۰px یک‌ستونه است و دکمهٔ ارسال تمام‌عرض.
- [ ] ارسال فرم خالی → با ۳۰۳ برمی‌گردد، خطاها زیر فیلدها با متن قرمز و `aria-invalid` نمایش داده می‌شود و مقادیر پرشده حفظ شده‌اند؛ چیزی در URL جز `mw-request=error` و `mw-request-token` (کلید تصادفی) نیست — هیچ دادهٔ شخصی در نشانی نمی‌رود.
- [ ] ارسال درست → پیام موفقیت با شمارهٔ پیگیری `MW-۲۰۲۶-…` نمایش داده می‌شود؛ رسید به ایمیل درخواست‌دهنده و هشدار به ایمیل مدیر می‌رسد (در محیط محلی با MailHog/Mailpit یا افزونهٔ لاگ ایمیل بررسی کنید).
- [ ] چهار ارسال پشت‌سرهم از یک IP → پیام «تعداد درخواست‌ها بیش از حد» (محدودیت پیش‌فرض ۳ در ساعت).
- [ ] با JavaScript خاموش فرم همچنان کامل کار می‌کند؛ با JS روشن، شمارندهٔ زندهٔ کاراکتر پیام (زیر متن) به‌روز می‌شود و پس از خطا فوکوس روی اولین فیلد نامعتبر می‌رود.
- [ ] پیشخوان → MusicWave: آیتم «درخواست‌ها و همکاری» با نشان تعداد درخواست‌های جدید، **درست بالای «MusicWave VIP»** قرار دارد.
- [ ] صندوق ورودی: آمار بالا، تب‌های وضعیت با شمارنده، فیلترهای نوع/نقش/اولویت، جست‌وجو (نام، ایمیل، تلفن، شمارهٔ پیگیری، موضوع، متن — با املای فارسی/عربی)، صفحه‌بندی، اقدام گروهی (تغییر وضعیت/اولویت/حذف).
- [ ] صفحهٔ جزئیات: پاسخ ایمیلی با قالب‌های آماده (وضعیت خودکار به «پاسخ داده‌شده» می‌رود)، یادداشت داخلی، تغییر وضعیت/اولویت، دکمه‌های پذیرش/رد/بایگانی، ویرایش فیلدها، تاریخچهٔ کامل، حذف با تأیید دومرحله‌ای.
- [ ] «ثبت دستی» (`view=new`) یک درخواست تلفنی/حضوری را با همان اعتبارسنجی ذخیره می‌کند (بدون ارسال ایمیل).
- [ ] «تنظیمات» (`view=settings`): خاموش‌کردن فرم → در فرانت‌اند پیام «فعلاً پذیرفته نمی‌شود» نمایش داده می‌شود؛ گیرنده‌های هشدار، Reply-To، رسید، امضا، محدودیت نرخ و انواع فعال ذخیره می‌شوند.
- [ ] ابزارها → صادرات/پاک‌کردن داده‌های شخصی: با ایمیل درخواست‌دهنده، گروه «درخواست‌های همکاری» صادر و پاک می‌شود.

## ۴. دروازه‌های خودکار

در ریشهٔ مخزن (نیاز به PHP 8.x CLI و Node 20):

```bash
# PHP — بدون وابستگی خارجی
php tests/run.php                       # آزمون‌های دامنه + یکپارچگی قالب
php tools/check-site-editor.php         # قراردادهای Site Editor / بخش‌های قالب
php tools/check-templates.php
php tools/check-script-translations.php

# با Composer (اختیاری، مطابق CI)
composer install
composer check:syntax && composer check:phpcs && composer check:phpstan

# JavaScript
npm ci
npm run lint:js                         # ESLint + wp-prettier روی هر دو بسته

# آزمون‌های سرتاسری ویرایشگر (Playwright) روی یک نصب در حال اجرا
npx playwright install chromium
WP_BASE_URL=http://localhost:8888 WP_USERNAME=admin WP_PASSWORD=password npm run test:e2e
```

خروجی مورد انتظار: همهٔ فرمان‌ها با کد خروج `0` تمام می‌شوند؛ `tests/run.php` در پایان `PASSED` چاپ می‌کند.

## ۵. ساخت بستهٔ نصب (ZIP)

```bash
php tools/package-release.php --destination=dist
```

فایل‌های ZIP قالب و افزونه‌ها در `dist/` (خارج از Git) ساخته می‌شوند و از **پیشخوان → افزونه‌ها/پوسته‌ها → بارگذاری** قابل نصب‌اند.

## ۷. عیب‌یابی سریع

| نشانه | علت محتمل | راه‌حل |
| --- | --- | --- |
| صفحهٔ انتشار ۴۰۴ می‌دهد | پیوندهای یکتا ثبت نشده | تنظیمات → پیوندهای یکتا → ذخیره |
| نشانی انتشارها هنوز `‎/music/…` است | قوانین بازنویسی قدیمی کش شده‌اند (افزونهٔ کش/آبجکت‌کش گزینهٔ `music_wave_release_permalink_rules` را کهنه نگه داشته) | تنظیمات → پیوندهای یکتا → ذخیره؛ کش آبجکت را خالی کنید |
| بخش دیدگاه روی صفحهٔ انتشار نیست | دیدگاه‌ها برای آن نوشته بسته‌اند و دیدگاهی وجود ندارد | ویرایش سریع → «اجازهٔ دیدگاه» را فعال کنید |
| منوی همبرگر باز نمی‌شود | اسکریپت `core/navigation` بارگذاری نشده (کش/بهینه‌ساز JS) | کش را پاک کنید؛ ادغام/تأخیر اسکریپت‌های `wp-includes` را برای `interactivity` خاموش کنید |
| رنگ‌های حالت روشن اعمال نمی‌شود | `data-mw-scheme` روی `<html>` نیست | افزونهٔ دیگری `language_attributes` را بازنویسی کرده؛ فیلتر `musicwave_native_color_scheme` را بررسی کنید |
| نوار پخش روی محتوا می‌افتد | `html.mw-has-player` حذف شده یا CSS قالب کش قدیمی است | کش مرورگر/افزونهٔ کش را خالی کنید |
| جست‌وجوی فارسی هنوز نتیجه نمی‌دهد | افزونهٔ جست‌وجوی دیگری `posts_search` را با اولویت بالاتر بازنویسی می‌کند یا `suppress_filters` روشن است | افزونه‌های جست‌وجو را موقتاً غیرفعال کنید؛ فیلتر `music_wave_script_aware_search` را بررسی کنید |
| ایمیل رسید/هشدار درخواست نمی‌رسد | `wp_mail()` روی هاست پیکربندی نشده یا گیرنده‌ای در تنظیمات نیست | یک افزونهٔ SMTP نصب کنید؛ در «درخواست‌ها و همکاری → تنظیمات» گیرنده و Reply-To را وارد کنید |
| فرم درخواست «نشست منقضی شد» می‌دهد | صفحهٔ فرم توسط کش کامل‌صفحه با نانس قدیمی ذخیره شده | صفحهٔ فرم را از کش مستثنا کنید یا عمر کش را زیر ۱۲ ساعت بگذارید |
| `npm run test:e2e` خطای ورود می‌دهد | نام کاربری/گذرواژه با نصب شما فرق دارد | متغیرهای `WP_USERNAME`/`WP_PASSWORD` را تنظیم کنید |
