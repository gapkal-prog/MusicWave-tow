## ۰. واژهنامه (اصطلاحات فنی به زبان ساده)

| اصطلاحی که در پنل میبینی | یعنی چه؟ | نام فنی |
|---|---|---|
| **لبه / CDN** | دامنهای عمومی که کاربر در لینک میبیند و فایل از آنجا میآید (مثل `files.example.com`). فایلها روی همان سرور شما یا روی سرویسهای مثل Cloudflare R2/Backblaze هستند. | Edge / CDN |
| **دامنهٔ عمومی / میزبان** | همان نام سایت در اینترنت، مثل `example.com` یا `files.example.com` (بدون `https://` و بدون اسلش آخر). | Host / Domain |
| **آدرس پایهٔ HTTPS** | آدرس کامل مسیر فایلها روی لبه، مثل `https://files.example.com/private`. | Base URL |
| **کلید مخفی امضای لینک (Edge secret)** | یک رشتهٔ تصادفی بلند که فقط شما و لبه آن را میدانید. با آن، لینکها «امضا» میشوند تا کسی نتواند لینک را دستکاری کند. با دکمهٔ «ایجاد کلید ۶۴ نویسهای» ساخته میشود. | Signing secret / HMAC key |
| **کلید مخفی سرور دانلود (Remote secret)** | همان مفهوم بالا، اما برای حالت قدیمی «انتقال به سرور دانلود». | Remote signing secret |
| **هدر مخفی احراز هویت مبدأ (Origin header)** | یک «رمز ورود» بین لبه و سرور شما: لبه این هدر را میفرستد و سرور مبدأ فقط درخواستهای دارای آن را قبول میکند. کاربر آن را نمیبیند. | Origin auth header |
| **امضا (Signature)** | اثر انگشت دیجیتال لینک؛ اگر یک حرف از لینک عوض شود، امضا باطل میشود. | HMAC-SHA256 |
| **نشست (Session)** | یک بلیت کوتاهعمر که هنگام شروع پخش صادر میشود و به کاربر/دستگاه گره میخورد؛ مانع کپیکردن لینک میشود. | Playback session |
| **arman کوتاهعمر / انقضا (exp)** | زمانی که بعد از آن لینک یا نشست بیاعتبار میشود. | TTL / expiry |
| **ارسال فایل توسط وبسرور (offload / sendfile)** | وقتی فایل را خود وبسرور (Nginx/Apache) میفرستد بهجای PHP؛ سریعتر و سبکتر است. | X-Sendfile / X-Accel-Redirect |
| **بستهبندی HLS** | شکستن یک فایل صوتی به قطعههای کوچک برای پخش تکهتکه. | HLS packaging |
| **رمزنگاری AES-128** | رمزگذاری قطعهها با یک کلید ۱۶ بایتی که فقط روی سایت شما میماند. | AES-128 |
| **ffmpeg / ffprobe** | دو برنامهٔ رایگان روی سرور که برای بستهبندی و خواندن مدت آهنگ لازم است. | ffmpeg, ffprobe |

## ۱. حالتهای تحویل (Delivery provider) — کدام را انتخاب کنم؟

در بالای تب، «حالت تحویل» را انتخاب میکنید. جدول زیر خلاصهٔ همهچیز است:

| حالت | فایل از کجا میآید؟ | چه بخشهایی لازم دارد | چیزهای ضروری برای این حالت |
|---|---|---|---|
| **`local`** | همان سرور وردپرس | فقط «تحویل محلی هوشمند» | هیچچیز؛ پیشفرض و سادهترین |
| **`proxy`** | همان سرور، ولی از دامنهٔ سایت عبور میکند (مخفیترین) | «نشست» + «تحویل محلی هوشمند» | تنظیم درست وبسرور برای ارسال سریع (اختیاری) |
| **`edge_signed`** | لینک کوتاهعمر روی دامنهٔ CDN | «لبه/CDN» + «آپلود خودکار» | آدرس پایهٔ HTTPS، کلید مخفی امضا، هدر مخفی مبدأ |
| **`edge_hls`** | قطعههای رمزنگاریشده روی CDN، کلید روی سایت | «لبه/CDN» + «HLS» + «آپلود خودکار» | همانند بالا + نصب `ffmpeg` روی سرور |
| **`remote_redirect`** | سرور دانلود خودتان (لینک عمومی) | «انتقال راهدور» + «آپلود خودکار» | آدرس پایهٔ راهدور و کلید مخفی امضای راهدور |

**توصیه:**
- فقط روی سرور خودت نگه میداری → `local` را دست نزن؛ همین حالا خودترمیمی و تازهسازی اثر انگشت روشن است.
- میخواهی بایتها روی CDN بروند ولی کلید روی سایت بماند (امن+سبک) → `edge_hls`.
- بالاترین مخفیکاری (حتی CDN هم مبدأ را نبیند) → `proxy`.
- پخش ساده بدون بستهبندی → `edge_signed`.

هر بخش در پنل یک **کارت با مرز مشخص** است؛ روی سر آن دو برچسب میبینی: «ضروری/اختیاری» و «در حالت فعلی فعال/بیاثر». با تغییر حالت تحویل، این برچسبها **خودکار** عوض میشوند.

## ۲. بخش «لبه / CDN»

برای حالتهای `edge_signed` و `edge_hls` **ضروری**.

| گزینه | ضروری؟ | توضیح ساده |
|---|---|---|
| **دامنهٔ عمومی لینکها** | اختیاری | دامنهای که در لینک نهایی دیده میشود، مثل `files.example.com`. خالی بگذاری، از دامنهٔ «آدرس پایه» استفاده میشود. |
| **آدرس پایهٔ HTTPS لبه** | **بله** | مثل `https://files.example.com/private`. باید با `https://` شروع شود وگرنه حالت لبه فعال نمیشود. |
| **کلید مخفی امضای لینک** | **بله** | رشتهٔ تصادفی حداقل ۳۲ نویسه؛ با دکمهٔ «ایجاد کلید ۶۴ نویسهای» بساز. تا وقتی خالی/کوتاه باشد، حالت لبه بهصورت ایمن به تحویل محلی برمیگردد. |
| **شناسهٔ کلید امضا** | اختیاری | یک برچسب کوتاه مثل `k1`. هنگام تعویض کلید، آن را عوض کن تا لینکهای قدیمی تا انقضای خودشان کار کنند. |
| **عمر هر لینک امضاشده** | اختیاری | ثانیه (۳۰۰ تا ۱۴۴۰۰). باید از طولانیترین آهنگ بیشتر باشد؛ مثلاً ۳۶۰۰ برای یک ساعت. |
| **هدر مخفی احراز هویت مبدأ** | **بله** | نام + مقدار یک هدر سفارشی (مثل `X-Origin-Token`). لبه آن را به سرور مبدأ میفرستد و سرور فقط درخواستهای دارای آن را قبول میکند. |
| **دامنههای مجاز اضافی** | اختیاری | اگر لینکها روی چند دامنه ساخته میشوند، با کاما جدا کن. برای زیردامنهها `*.` بگذار. |
| **تست اتصال لبه** | — | یک دکمه؛ یک درخواست سبک میفرستد و میگوید اتصال و هدر درست است یا نه. |

> **چرخش کلید بدون قطعی:** کلید جدید را ذخیره کن، «شناسهٔ کلید امضا» را عوض کن. لبه باید نقشهٔ شناسه→کلید را داشته باشد.

## ۳. بخش «نشستهای پخش و جلوگیری از اشتراکگذاری لینک»

برای حالتهای `edge_signed`، `edge_hls` و `proxy` **توصیهشده** (اختیاری).

| گزینه | پیشفرض | توضیح ساده |
|---|---|---|
| **فعالسازی نشستهای پخش** | روشن | هر پخش یک بلیت کوتاهعمر میسازد؛ بدون آن هیچ قطعه/کلیدی سرو نمیشود. |
| **طول عمر نشست** | ۶۰ ثانیه | با هر درخواست معتبر تمدید میشود. کوتاهتر = امنتر. |
| **حداکثر پخش همزمان** | ۱ | بیشتر از این تعداد، قدیمیترین نشست آزاد میشود (محدودکردن اشتراکگذاری حساب). |
| **مهلت آزادسازی اجاره** | ۱۲۰ ثانیه | نشست بلااستفاده پس از این مدت آزاد میشود. |
| **اتصال به آیپی** | روشن | لینک کپیشده در آیپی دیگر کار نمیکند. اگر کاربران موبایل زیاد جابهجا میشوند و قطعی آزارنده است، خاموش کن. |
| **اتصال به مرورگر (User-Agent)** | خاموش | امنیت بیشتر، اما ممکن است برخی پخشکنندههای ثالث را محدود کند. |
| **تمدید کشویی** | روشن | تا وقتی پخش ادامه دارد، عمر نشست خودکار تازه میشود. |
| **محل نگهداری نشست** | جدول | توضیحی است: نشستها در یک جدول اختصاصی و دقیق ذخیره میشوند. |

> عمر نشست ≠ عمر لینک: `session_ttl` عمر کوکی/بلیت است و `signed_url_ttl` عمر امضای لینک. دومی باید از طول آهنگ بیشتر باشد.

## ۴. بخش «بستهبندی HLS و رمزنگاری»

فقط برای حالت `edge_hls` **ضروری**. نیازمند `ffmpeg` روی سرور.

| گزینه | پیشفرض | توضیح ساده |
|---|---|---|
| **فعالسازی مسیرهای HLS** | خاموش | با انتخاب `edge_hls` خودکار روشن میشود. |
| **رمزنگاری جریان** | AES-128 | «خاموش» یعنی قطعهٔ لو رفته قابل پخش است؛ فقط برای اضطراب. |
| **کیفیتهای خروجی** | ۱۲۸ و ۳۲۰ | هر کیفیت بیشتر = CPU و فضای بیشتر. |
| **طول هر قطعه** | ۶ ثانیه | کوتاهتر = شروع سریعتر پخش؛ بلندتر = فایلهای کمتر. |
| **زمان بستهبندی** | هنگام آپلود | همیشه در پسزمینه اجرا میشود و درخواست کاربر را معطل نمیکند. |
| **مسیر قطعات** | از CDN | «قطعات از سایت عبور کنند» فقط اگر CDN نداری یا میخواهی همهچیز از یک دامنه باشد. |
| **مسیر ffmpeg / ffprobe** | `ffmpeg` / `ffprobe` | اگر در PATH نیست، مسیر مطلق بده. |

> **کلید AES هرگز روی CDN نمیرود.** قطعهها میتوانند روی CDN باشند، اما بدون کلید (که فقط با نشست معتبر از سایت صادر میشود) بیارزشاند.

## ۵. بخش «آپلود خودکار به سرور دانلود/CDN»

برای حالتهای `remote_redirect`، `edge_signed` و `edge_hls` **توصیهشده** (اختیاری). اگر فایلها روی همان سرور سایت میمانند، لازم نیست.

| گزینه | پیشفرض | توضیح ساده |
|---|---|---|
| **فعالسازی صف بارگذاری** | خاموش | روشن = هر فایل تازه خودکار روی سرور مقصد منتقل میشود. |
| **روش انتقال** | Webhook | اگر فقط «یک لینک آپلود» داری → `webhook`. برای R2/B2/MinIO → `s3`. برای Nextcloud → `webdav`. برای SSH → `sftp`. |
| **نشانی endpoint** | — | آدرس HTTPS همان روش؛ آدرسهای خصوصی/داخلی رد میشوند (ضد SSRF). |
| **توکن/اعتبارنامه** | — | با دکمهٔ «ایجاد کلید ۶۴ نویسهای» یا مقدار واقعی سرور مقصد. **سربسته ذخیره میشود** و هرگز در لاگ نمیآید. |
| **نام سطل / منطقه / Access-Key / Secret-Key** | — | فقط برای `s3`. |
| **میزبان/کاربر/رمز/اثر انگشت SFTP** | — | فقط برای `sftp`. «اثر انگشت» یک رشتهٔ `SHA256:...` از کلید سرور است؛ برای جلوگیری از حملهٔ مرد میانراه توصیه میشود. |
| **پیشوند مسیر مقصد** | — | مثلاً `musicwave/protected`. |
| **سقف اندازهٔ فایل** | ۰ (بیمحدودیت) | برای جلوگیری از آپلود فایلهای غولآسا عدد بگذار. |
| **حفظ نسخهٔ محلی + تأیید** | روشن | فایل محلی فقط پس از تأیید موفق آپلود حذف میشود. |
| **تلاش مجدد/همروندی/آستانهٔ S3** | ۵ / ۲ / ۱۰۰ | تعداد تلاش خودکار، تعداد فایل همزمان، و مرز فایلهای چندبخشی. |
| **غیرفعالکردن بررسی TLS** | خاموش | فقط برای آزمایش محلی با گواهی خودامضا؛ در سایت واقعی هرگز روشن نکن. |
| **ابزارها** | — | «تست اتصال آپلود»، «همگامسازی کل کتابخانه»، «وضعیت صف». |

> **قاعدهٔ مهم:** آپلود فقط وقتی انجام میشود که حالت تحویل به بایتهای خارجی نیاز داشته باشد. اگر حالت `local`/`proxy` باشد، این بخش «بیاثر» میشود و هیچ بایتی از سرور خارج نمیشود.

## ۶. بخش «تحویل محلی هوشمند»

برای حالتهای `local` و `proxy` مرتبط است. **بدون نیاز به سرور خارجی.**

| گزینه | پیشفرض | توضیح ساده |
|---|---|---|
| **تشخیص خودکار روش ارسال فایل** | روشن | بر اساس نوع وبسرور، بهترین روش را **پیشنهاد** میدهد (تغییر خودکار نمیدهد). |
| **ترمیم خودکار پوشه و سپرهای حفاظتی** | روشن | اگر `.htaccess`/`web.config` روزی حذف شود، خودکار بازسازی میشود. |
| **تازهسازی اثر انگشت فایل** | روشن | اگر فایل با همان حجم قبلی جایگزین شود، اثر انگشت (checksum) دوباره محاسبه میشود. |
| **اندازهٔ قطعهٔ پخش** | ۱۰۲۴ KB | روی هاست کمحافظه کوچکتر بگذار. |

## ۷. سؤالهای پرتکرار

**«کلید ۶۴ نویسهای» را از کجا بیاورم؟**
از داخل پنل: کنار هر فیلد رمز، دکمهٔ «ایجاد کلید ۶۴ نویسهای» هست؛ یک بار کلیک کافی است. (برای هدر مخفی مبدأ و کلید امضای لبه و اعتبارنامههای آپلود هم همین دکمه هست.)

**«ضروری» یعنی چه؟**
یعنی برای فعالشدن درست حالت انتخابی باید پر شود؛ وگرنه آن حالت ایمن غیرفعال میماند (fail-closed). «اختیاری» یعنی اگر خالی بماند، پیشفرض امن اعمال میشود.

**چطور بفهمم یک بخش روی حالت فعلی اثر دارد یا نه؟**
روی سر هر کارت، برچسب «در حالت فعلی فعال/بیاثر» هست و با تغییر حالت تحویل خودکار بهروز میشود.

**مقدارها را کجا ببینم؟**
هر گزینه یک آیکن «؟» دارد؛ با نگهداشتن ماوس یا با کیبورد روی آن، توضیح کامل نمایش داده میشود.

**اگر چیزی خراب شد چه؟**
حالتهای لبه در صورت نبود کلید/آدرس، ایمن به تحویل محلی برمیگردند و هرگز لینک بدون امضا صادر نمیکنند. `local` و `remote_redirect` هم رفتار قبلی خود را حفظ میکنند.

## ۸. نمونهٔ پیکربندیهای آماده

**الف) فقط سرور خودم (سادهترین):**
`delivery_provider = local` — بقیه گزینهها را دست نزن. خودترمیمی و تازهسازی اثر انگشت از قبل روشن است.

**ب) CDN + رمزنگاری (پیشنهادی برای بیشتر سایتهای فروش فایل):**
1. `delivery_provider = edge_hls`
2. «آدرس پایهٔ HTTPS لبه» را پر کن.
3. با دکمهٔ «ایجاد کلید»، «کلید مخفی امضای لینک» و «هدر مخفی مبدأ» را بساز و مقدار هدر را روی سرور/CDN تنظیم کن.
4. «تست اتصال لبه» را بزن تا سبز شود.
5. اگر فایلها روی سرور جداگانهاند، بخش «آپلود خودکار» را روشن و روش انتقال را انتخاب کن، سپس «همگامسازی کل کتابخانه» را یک بار بزن.
6. مطمئن شو `ffmpeg` روی سرور نصب است؛ سپس داراییها را بستهبندی کن.

**ج) مخفیترین حالت:**
`delivery_provider = proxy` + در بخش «ارسال فایل توسط وبسرور»، وبسرور را روی `xaccel`/`xsendfile` بگذار و location داخلی را طبق نمونهٔ کد پنل تنظیم کن.
